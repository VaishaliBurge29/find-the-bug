🐞 How to play

BugHunt Shop looks like a normal online shop — but it contains 41 deliberately planted bugs. Your job: find them like a professional tester, report them, and learn why each one happens.

1. Join

Click 🐞 Bug Hunt in the bottom-right corner and choose a nickname.

2. Explore & test

Use the shop like a customer — then like a tester. Try boundaries, invalid input, odd sequences, the keyboard, DevTools and API tools like Postman or Hoppscotch.

3. Report

Pick the page, feature and category, then describe what happened (steps, expected vs. actual). A clear report matters — just like in real life.

4. Learn

Each confirmed bug shows why it happens, how to prevent it and the ISTQB test technique that finds it.

Techniques that will help

  • Boundary value analysis — test min−1, min, max, max+1
  • Equivalence partitioning — one value from each valid and invalid group
  • Decision tables — combinations of conditions (e.g. coupon valid/expired × first/repeat use)
  • State transition testing — logged in/out, in stock/out of stock, applied/not applied
  • Error guessing — what usually goes wrong? (double clicks, HTML in inputs, changed IDs)
  • Checklist-based testing — accessibility (WCAG), security (OWASP), formatting
